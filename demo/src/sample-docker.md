# Docker コンテナのホスティング比較

コンテナ化が普及し、どこで動かすかの選択肢が増えた。本記事では自社に合うホスティングを選ぶ軸と、主要サービスの違いを整理する。

## 背景

Docker とマイクロサービスの普及で、アプリケーションをコンテナで配布するのが一般的になった。一方で運用の複雑さも増しており、選択肢が多岐にわたるため、何を基準に選ぶかが課題になっている。

## 評価軸

選定では次の4つの軸を見る。

- コスト構造：従量課金か固定費か
- 運用負荷：サーバーレスか自分で管理するか
- 拡張性：オートスケールとリージョン展開
- ロックイン：可搬性と標準仕様への準拠

## サービスの比較

### サーバーレス型

Google Cloud Run はゼロスケールに対応し、起動が速い。AWS ECS on Fargate は AWS の他サービスとの統合が強みで、Azure Container Apps は KEDA を基盤にしている。

### PaaS と自前運用

Render や Fly.io は開発体験が良く、グローバルエッジも使える。VPS + Docker Compose は低コストだが、運用は自前になる。

## ユースケース別の選び方

個人の PoC や運用ゼロで速度を優先するなら Render / Fly.io が向く。トラフィックの変動が大きい急成長のサービスには Google Cloud Run が合う。すでに AWS 資産がある大規模企業は ECS on Fargate が自然な選択になる。

| ケース | 推奨 |
| --- | --- |
| 個人・PoC | Render / Fly.io |
| 急成長 Web | Cloud Run |
| 大規模企業 | Fargate |

## まとめ

フェーズに応じて、ポータビリティを意識した選定をするのがよい。
